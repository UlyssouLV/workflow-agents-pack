# V0.8.1 — Refonte graphique du cockpit

Parent : [#123](https://github.com/UlyssouLV/workflow-agents-pack/issues/123)

## Problème

Le cockpit garde le « style minimal » de la 0.3.0 : une feuille `style.css` écrite à la main (fond clair, couleurs en dur, aucune variable), des pages qui s’empilent au fil des versions (liste, détail, Sessions, terminal, codespace) sans hiérarchie visuelle ni identité. Ce qui demande une action (intervention humaine requise, réponse attendue, clone sale) se distingue mal de ce qui n’est qu’informatif ; l’en-tête, l’encart Agents et l’état GitHub sont éparpillés ; la page Sessions est une liste plate qui grossit sans fin ; le terminal et Monaco n’ont rien à voir avec le reste de la page. Le produit a désormais un nom et un logo (**HéphaïstOS**) que l’interface ne montre pas.

## Solution

Un vrai design du cockpit, **sans changer ses capacités** : mêmes données, mêmes URLs, mêmes actions. La **maquette validée** fait référence : [`docs/specs/v0.8.1-maquette-cockpit.html`](v0.8.1-maquette-cockpit.html) (direction **C · Atelier**, retenue ; A et B restent dans la maquette pour mémoire). Chaque ticket cite l’écran qu’il reproduit.

- **Pile** : Tailwind v4 (`@tailwindcss/vite`) et shadcn/ui (composants copiés dans `orchestrator/cockpit/src/components/ui/`, au-dessus de Radix), lucide-react, sonner, `class-variance-authority`, `clsx`, `tailwind-merge`. Même technique qu’ArgOS (son ADR 0016), identité propre. ADR 0015.
- **Identité HéphaïstOS, direction Atelier** :
  - thème **sombre uniquement**, neutres gris acier (`#111113` fond, surfaces `#17171a` / `#1e1e22`, filets `#2b2b31`), bouton principal clair, focus orange ;
  - polices **Geist** (titres et texte) et **Geist Mono** (code, terminal, éditeur), **embarquées** en woff2 (licence OFL) : aucune requête vers un CDN, l’instance peut être lue par tunnel sans Internet ;
  - **code couleur des états**, le même partout : orange = il vous faut agir (intervention humaine requise, réponse attendue, clone sale) ; bleu = un agent travaille ; violet = Pilote (atténué et en pointillés quand il est en pause, avec la raison) ; vert = succès (CI ok, terminée, fermé) ; rouge = échec ; gris = neutre ou inconnu ;
  - pastille animée pour « travaille » et « réponse attendue », coupée par `prefers-reduced-motion` ;
  - logo complet sur la page de connexion ; emblème recadré (enclume et anneau d’agents) + mot-symbole « Héphaïst**OS** » dans la barre latérale ; favicon tiré de l’emblème. Source : [`docs/img/hephaistos/logo.png`](../img/hephaistos/logo.png). Titre d’onglet « HéphaïstOS » (avec `(n)` réponses attendues devant, comme aujourd’hui).
- **Coque** : barre latérale fixe (marque, **Repos**, **Sessions** avec le compteur de réponses attendues, encart **Agents** avec la commande `sudo wap-runtime auth …` quand un agent n’est pas connecté, compte GitHub ou bandeau d’erreur GitHub, **Déconnexion**) ; sur téléphone, une barre du haut (menu, marque, compteur) ouvre la barre latérale en panneau coulissant. Chaque page a un en-tête collant (fil d’Ariane, titre, actions).
- **Repos (`/`)** : résumé en tête (à vous d’agir / agents au travail / repos en pilote), puis tableau dense (repo et badges, version ouverte, barre de progression X/Y, étape, lu à) ; ligne entière cliquable ; « humain requis » en tête et marqué d’un liseré orange ; erreur de lecture en pastille rouge ; cartes sur téléphone. Message « Aucun repo lié » avec la commande `repo add`.
- **Détail (`/repos/<owner>/<name>`)** : alerte orange quand une intervention humaine est requise ; grille : à gauche une carte par version (progression, signaux, tableau des enfants, PR avec brouillon et checks CI), puis les bugs ouverts ; à droite le panneau **Lancer une session** (interrupteur Pilote, Agent, Modèle préféré, Branche, Modèle de la session, **Nouvelle session**, raison sous le bouton quand il est désactivé, avec le lien vers la session ouverte) et une carte repo (URL, étape, lu à). « Lancement refusé » en alerte en ligne ; préférence enregistrée confirmée par un toast.
- **Clone sale** : **dialogue modal** (Radix AlertDialog) avec fichiers modifiés, diff, **Annuler** / **Jeter** / **Reprendre** ; Échap = Annuler.
- **Sessions (`/sessions`)** : **regroupées par repo** — une carte par repo avec le nombre de sessions et une pastille (réponse attendue / ouverte / aucune ouverte). Ordre des groupes : repos qui attendent une réponse, puis ceux qui ont une session ouverte, puis les autres. Dans un groupe : sessions ouvertes toujours visibles ; sessions fermées repliées derrière « N sessions fermées » (repliable, état non mémorisé), les plus récentes d’abord. Regroupement côté front à partir de `/api/sessions` inchangé.
- **Session (`/sessions/<id>`, `/sessions/<id>/codespace`)** : en-tête (fil d’Ariane repo, titre `/implement #n` ou commande, état ou activité, **Terminer**), carte de métadonnées (titre, agent, modèle, branche, commande, durée, liens précédente / suivante), onglets Terminal / Codespace. **Terminer** demande confirmation dans un **dialogue** (au lieu de `window.confirm`). Terminal : barre « Vous avez la main » / « Lecture seule — Prendre la main » ; relecture d’une session fermée avec ses contrôles. Codespace : identité (repo, branche, HEAD, « En direct »), arbre avec marqueurs Git, onglets de fichiers, bouton **Diff avec HEAD** ; instantané avec son bandeau et ses entrées « non conservé ».
- **xterm et Monaco** : thèmes dérivés des mêmes variables (fond, sélection, curseur, couleurs ANSI, gouttière, couleurs Git), police Geist Mono.
- **Connexion (`/login`)** : logo complet, carte de formulaire, erreur en alerte.
- **Téléphone** : liste, détail, Sessions et connexion utilisables à ~400 px ; terminal et codespace visibles et lisibles sans débordement horizontal de la page, sans être optimisés (arbre au-dessus de l’éditeur).

## User stories

### Identité et coque

1. En tant qu’utilisateur, je veux reconnaître HéphaïstOS (logo, nom, onglet) en ouvrant le cockpit, pour savoir où je suis.
2. En tant qu’utilisateur, je veux une navigation toujours visible (Repos, Sessions) avec le nombre de réponses attendues, pour aller à ce qui m’attend en un clic.
3. En tant qu’utilisateur, je veux voir dans la navigation si Claude Code et Cursor sont connectés et, sinon, la commande à lancer sur l’hôte, sans revenir à la page d’accueil.
4. En tant qu’utilisateur, je veux voir sur toutes les pages si l’instance lit GitHub (compte connecté ou bandeau d’erreur avec la commande à lancer).
5. En tant qu’utilisateur sur téléphone, je veux ouvrir la navigation par un menu, pour garder la page lisible.
6. En tant qu’utilisateur, je veux un en-tête de page avec le fil d’Ariane et les actions de la page, toujours visible au défilement.

### Couleurs d’état

7. En tant qu’utilisateur, je veux que tout ce qui attend une action de ma part soit orange partout (badges, lignes, compteur), pour le repérer d’un coup d’œil.
8. En tant qu’utilisateur, je veux distinguer à la couleur un agent qui travaille (bleu), un repo en pilote (violet), un succès (vert), un échec (rouge) et un état neutre (gris).
9. En tant qu’utilisateur sensible aux animations, je veux que les pastilles animées s’arrêtent quand mon système demande moins de mouvement.

### Repos

10. En tant qu’utilisateur, je veux un résumé en tête de la liste (à moi d’agir, agents au travail, repos en pilote).
11. En tant qu’utilisateur, je veux un tableau dense de tous les repos, ceux qui attendent quelqu’un en tête, et cliquer n’importe où sur une ligne pour ouvrir le détail.
12. En tant qu’utilisateur, je veux la progression d’une version en barre et en X/Y.
13. En tant qu’utilisateur sur téléphone, je veux les repos en cartes plutôt qu’en tableau.

### Détail d’un repo

14. En tant qu’utilisateur, je veux une alerte en tête quand une intervention humaine est requise.
15. En tant qu’utilisateur, je veux chaque version dans sa carte (progression, signaux, enfants, PR et checks CI) et les bugs ouverts à part.
16. En tant qu’utilisateur, je veux un panneau « Lancer une session » groupé (Pilote, agent, modèles, branche, Nouvelle session) et la raison sous le bouton quand je ne peux pas lancer.
17. En tant qu’utilisateur, je veux activer le Pilote par un interrupteur et voir une confirmation passagère quand la préférence est enregistrée.
18. En tant qu’utilisateur, je veux que le choix « clone sale » soit un dialogue modal qui bloque le reste de la page jusqu’à mon choix, Échap valant Annuler.

### Sessions

19. En tant qu’utilisateur, je veux les sessions regroupées par repo, les repos qui attendent une réponse en premier.
20. En tant qu’utilisateur, je veux voir les sessions ouvertes de chaque repo et replier les sessions fermées, pour que la page ne grossisse pas sans fin.

### Session

21. En tant qu’utilisateur, je veux une carte de métadonnées claire (agent, modèle, branche, commande, durée, chaîne) au-dessus des onglets Terminal / Codespace.
22. En tant qu’utilisateur, je veux confirmer **Terminer** dans un dialogue de la page plutôt qu’une boîte du navigateur.
23. En tant qu’utilisateur, je veux voir si j’ai la Main ou si je suis en lecture seule, et prendre la Main d’un bouton.
24. En tant qu’utilisateur, je veux que le terminal, la relecture et Monaco (fichier et diff) aient les couleurs et la police du cockpit.
25. En tant qu’utilisateur, je veux le codespace et l’instantané dans la même identité, marqueurs Git compris.

### Connexion

26. En tant qu’utilisateur, je veux une page de connexion avec le logo HéphaïstOS.

### Qualité

27. En tant que mainteneur, je veux un seul jeu de variables pour toutes les couleurs, rayons et polices, et aucune couleur en dur hors des variables.
28. En tant que mainteneur, je veux que les tests du cockpit visent rôles et libellés, jamais des classes Tailwind.
29. En tant qu’utilisateur, je veux que toutes les capacités livrées jusqu’à la 0.8.0 marchent comme avant.

## Décisions d’implémentation

- **Dépendances** (cockpit) : `tailwindcss`, `@tailwindcss/vite`, `tw-animate-css`, Radix (`react-alert-dialog`, `react-dialog`, `react-collapsible`, `react-switch`, `react-tabs`, `react-tooltip`, `react-label`, `react-slot`), `lucide-react`, `sonner`, `class-variance-authority`, `clsx`, `tailwind-merge`, polices Geist (woff2 copiés dans `src/assets/fonts/` avec leur licence OFL, ou paquet npm qui les fournit en local). **Versions exactes** pour ces nouvelles dépendances ; les `^` existantes ne changent pas.
- **Tokens** : variables CSS sur `:root` (fond, surfaces, filets, texte, texte atténué, principal, attention, agent, pilote, succès, échec, neutre, rayon, polices), exposées à Tailwind par `@theme inline`. `style.css` disparaît.
- **Composants** : `components/ui/` (button, card, alert, alert-dialog, dialog, sheet, tabs, switch, native-select, collapsible, tooltip, label, table, skeleton, sonner, badge) ; `cn()` dans `lib/utils.ts`. Les listes déroulantes restent des `<select>` natifs stylés (`native-select`), rôle `combobox` inchangé. Pilote : Switch (rôle `switch`). Clone sale et Terminer : AlertDialog. Erreurs persistantes : Alert ; toasts sonner pour les confirmations passagères uniquement.
- **Onglets** Terminal / Codespace et onglets de fichiers : rôles `tablist` / `tab` / `tabpanel` conservés (Radix Tabs ou ARIA existante). Le terminal reste monté quand on change d’onglet ; la Main n’est pas libérée.
- **Arbre du codespace** : arbre ARIA maison (`tree` / `treeitem` / `group`) conservé, restylé.
- **Thèmes** : un thème xterm et un thème Monaco (`defineTheme`) construits à partir des mêmes valeurs que les tokens.
- **Routage** : routeur maison et URLs inchangés ; les liens rechargent la page comme aujourd’hui.
- **Sessions regroupées** : fonction pure de regroupement et de tri (testée seule), à partir de `/api/sessions` inchangé.
- **Logo** : emblème recadré et favicon tirés de `docs/img/hephaistos/logo.png`, servis depuis `src/assets/` (PNG optimisé) ; `index.html` : titre « HéphaïstOS », favicon.
- **Runtime** : aucune route ni donnée nouvelle ; seuls les fichiers servis du front changent.
- **Version du paquet** : `0.8.1`.
- **Docs** : glossaire **HéphaïstOS** ; ADR 0015 « Tailwind et shadcn/ui pour le cockpit ».

## Décisions de test

- Bon test = comportement observable du cockpit par rôles et libellés (Vitest + Testing Library), pas de classe Tailwind ni de couleur.
- Tests existants adaptés seulement là où un rôle change : case Pilote → `switch` ; clone sale → `alertdialog` ; Terminer → dialogue de confirmation au lieu de `window.confirm` ; encart Agents et état GitHub lus dans la navigation.
- Nouveaux : navigation (liens, compteur, Agents, Déconnexion, panneau mobile) ; résumé de la liste ; ligne cliquable ; regroupement et tri des sessions (fonction pure + rendu, sessions fermées repliées) ; Échap ferme les dialogues ; titre d’onglet « HéphaïstOS ».
- Suites pytest et vitest 0.1.0–0.8.0 restent vertes ; `npm run build` passe ; quality gate Sonar.
- Tests humains : sur une vraie instance, parcourir les 9 écrans de la maquette (connexion, repos, détail, clone sale, Sessions, terminal en direct, codespace, relecture, instantané) sur ordinateur et sur téléphone, en direction Atelier ; vérifier que chaque action livrée marche comme avant (lancer, Pilote, Reprendre / Jeter, Terminer, Prendre la main, diff, notifications).

## Hors périmètre

- Nouvelles fonctionnalités métier ; nouvelle route ou donnée côté runtime.
- Thème clair ; choix de thème par l’utilisateur.
- Navigation sans rechargement (react-router).
- Renommage de la CLI, du paquet, des images ou du README en HéphaïstOS ; refonte de la doc ou du README.
- Directions A (Forge) et B (Réseau) de la maquette.
